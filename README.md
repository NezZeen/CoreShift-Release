VPN-клиент для подписок на Windows, Linux и Android. Он сам держит соединение: следит за ядром, сервером и сетью и чинит то, что сломалось, без участия пользователя.

Внутри три прокси-ядра — **Xray, sing-box и mihomo**. Если текущее ядро упало, не приняло конфиг или перестало пропускать трафик, CoreShift переключается на следующее, а туннель и DNS при этом не пересоздаются, и соединения у программ не рвутся.

Готовые сборки для Windows, Linux и Android — на странице [Releases](https://github.com/NezZeen/CoreShift-Release/releases). Чат: [t.me/CoreShift_app](https://t.me/CoreShift_app).

## Что умеет клиент

### Подписки и серверы

- **Форматы.** Ссылки `https://…` на подписку, списки серверов VLESS (Reality, XHTTP, gRPC, WS…), VMess, Trojan, Shadowsocks, Hysteria2, TUIC, AnyTLS, WireGuard, JSON Xray (например, от Remnawave) и конфиги Clash. Каждый сервер запускается на ядре, которое его поддерживает.
- **Добавление.** Кнопкой «Добавить в CoreShift» на странице подписки панели (ссылка `coreshift://add/<ссылка>`), из буфера обмена (подходят и ссылки для Happ, v2rayNG, v2RayTun, Hiddify, Clash, sing-box), по QR-коду или вручную. Перед добавлением CoreShift спрашивает подтверждение и не показывает ключ из ссылки. Система открывает CoreShift только по `coreshift://`, чужие схемы он не перехватывает.
- **Обновление подписок** по интервалу, который предлагает панель, или по своему. Видны трафик и срок подписки в тех же единицах, что в панели; за несколько дней до конца срока и при 90% трафика появляется предупреждение с кнопкой «Продлить» и уведомление.
- **Выбор сервера.** Пинг до всех серверов, «Самый быстрый» одной кнопкой. Серверы, которые не отвечают на обычный пинг, проверяются настоящим запросом через ядро.
- **«Другой сервер».** Если сервер перестал отвечать, CoreShift сам переходит на живой сервер подписки и пишет, какой не отвечает.

### Устойчивость соединения

- **Три ядра с автопереключением.** Порядок Xray → sing-box → mihomo; когда основное ядро снова в порядке, CoreShift может вернуться на него сам.
- **Проверка связи** через туннель: один адрес, запасные только при сбое. Проверка, прерванная сменой ядра, не считается неудачной.
- **«Нет сети».** CoreShift отличает пропавший интернет от упавшего сервера. Без сети он не перебирает ядра и серверы, а ждёт, пишет «Нет сети» и продолжает работу, когда сеть вернётся. «Подключить» без сети показывает «Ждём сеть…» и подключается само.
- **DNS после сна телефона.** DNS-соединения туннеля обновляются после сна и долгого простоя, запрос повторяется один раз.
- **Обход DPI.** Одним переключателем начало защищённого соединения режется на части, и фильтры провайдера перестают его узнавать.

### Маршрутизация

- Всё через VPN, кроме исключений, или только выбранное.
- «Российские сайты напрямую» одним переключателем; Google и YouTube при этом всегда идут через VPN. Базы сайтов встроены в приложение и раз в неделю обновляются, но новая база принимается, только если проходит проверку.
- Готовые наборы популярных сервисов, свои сайты (через VPN, мимо VPN, заблокировать), домены на кириллице.
- Отдельные программы на Windows и Linux и приложения на Android — через VPN или мимо него.
- Режим прокси без TUN, когда «Все приложения через VPN» выключено.
- Локальная сеть (роутер, принтеры, виртуальные машины) работает при включённом VPN.

### Защита от утечек

- DNS перехватывается на уровне системы (на Windows NRPT и `strict_route`, на Linux systemd-resolved, resolvconf, netconfig или `resolv.conf`), каждое изменение записывается в журнал отката и снимается даже после сбоя.
- Можно блокировать DNS-over-TLS. Встроенная проверка показывает, видят ли сайты настоящий DNS.
- Если IPv6 выключен, его трафик не идёт мимо VPN: туннель забирает его и сразу отклоняет, программы без задержек переходят на IPv4.

### Интерфейс

- Пять вкладок, одинаковых на ПК и телефоне: Главная, Серверы, Правила, Журнал, Настройки. Тонкие настройки — в «Дополнительно».
- На главной: IP и страна, скорость, трафик за неделю, тест скорости через speedtest.net через VPN или без него.
- Журнал: одинаковые строки ядер сворачиваются («— ещё N раз за 30 с»), ошибки красные, предупреждения жёлтые, поиск и фильтр. Копия для поддержки скрывает ссылки подписок и UUID.
- Тёмная и светлая темы, автоподключение при запуске, трей на ПК, уведомление со скоростью на Android. С выключенным экраном Android реже опрашивает трафик и связь и тратит меньше батареи.
- Кнопка «Поддержка» ведёт в чат провайдера, если панель его указала.

### Обновления

- **CoreShift** раз в день ищет новую версию в публичном [NezZeen/CoreShift-Release](https://github.com/NezZeen/CoreShift-Release). Манифест подписан Ed25519 и проверяется встроенными ключами, установщик — по SHA-256. На Windows обновление ставится, когда VPN выключен, и не рвёт соединение; на Android его ставит система по запросу; на Linux приложение сообщает о новой версии, а ставит её пакетный менеджер.
- **Ядра** обновляются сами из релизов своих проектов. Новое ядро сначала проверяется запуском; если оно не стартует, остаётся прежнее.

## Как устроено

| Папка | Что там |
| --- | --- |
| `engine/` | Движок на Go. На ПК работает системной службой `coreshiftd`, на Android — библиотекой внутри приложения (`engine/mobile`, gomobile). |
| `app/` | Интерфейс на Flutter для Windows, Linux и Android (и веб-демо). На ПК говорит со службой по локальному HTTP API, на Android вызывает движок напрямую. |
| `packaging/` | Сборка и выпуск: установщик Windows (Inno Setup), APK, пакеты Linux, подписанные манифесты обновлений, публикация. Подробнее — [packaging/README.md](packaging/README.md) и [packaging/linux/README.md](packaging/linux/README.md). |
| `docs/` | Результаты проверок: функций и безопасности. |
| `prototype/` | Исходный HTML-макет интерфейса; в приложении переписан на Flutter. |

### Движок (`engine/internal`)

| Пакет | Задача |
| --- | --- |
| `service` | Сердце службы: состояние подключения, переподключение, «Нет сети», выбор и смена сервера, журнал, локальное API и поток событий для интерфейса. |
| `supervisor` | Запускает ядра отдельными процессами, проверяет их здоровье и переключает на следующее при сбое. |
| `core` | Конфиги для Xray, sing-box и mihomo из одного описания сервера. |
| `tunlayer` | Постоянный слой TUN + DNS на sing-box (fake-ip): живёт отдельно от сменяемого ядра. |
| `dnsguard` | Направляет DNS системы в туннель и откатывает изменения по журналу. |
| `dnswake` | Обновляет DNS-соединения туннеля после сна устройства (Android). |
| `subscription`, `node` | Разбор подписок всех форматов и описание серверов. |
| `store` | Настройки и подписки на диске, атомарная запись. |
| `ruleset` | Встроенные базы сайтов для правил и их проверка при обновлении. |
| `ping` | Пинг серверов, проверка маршрута по умолчанию («есть ли сеть»). |
| `doh` | DNS-over-HTTPS для имён серверов, которые не находит DNS провайдера. |
| `apps`, `proc` | Список запущенных программ для правил и управление процессами. |
| `coreupdate` | Обновление ядер из их релизов на GitHub. |
| `selfupdate` | Самообновление CoreShift: поиск релиза, проверка подписи и SHA-256, загрузка. |
| `fsutil` | Общие файловые помощники. |

Команды: `engine/cmd/coreshiftd` — служба и её подкоманды (установка службы, проверка обновлений, подключение без интерфейса), `engine/cmd/coreshift-release` — подготовка и подпись файлов выпуска, обновление встроенных баз правил.

### Интерфейс (`app/lib`)

| Папка | Что там |
| --- | --- |

### Главные решения

- **Ядро сменяемо, туннель постоянен.** Ядра работают отдельными процессами с SOCKS-входом (с логином и паролем на каждый запуск). TUN и DNS держит отдельный слой, поэтому смена ядра не трогает маршруты и DNS системы.
- **Права разделены.** На Windows служба работает от SYSTEM, интерфейс — без прав; на Linux служба — root в песочнице systemd, на Android — `VpnService`.
- **Локальное API защищено.** Служба слушает `127.0.0.1` на случайном порту, принимает только запросы с токеном из `api.json` и правильным `Host`, а приложение доверяет службе, только когда та докажет знание токена (HMAC). На Windows службой пользуются только члены группы «CoreShift Users», на Linux — группы `coreshift`. Размер запросов, время ожидания и число потоков событий ограничены.
- **Обновления проверяются подписью**, ключ подписи в репозиторий не попадает.

## Разработка

Нужны Go, Flutter и Git. Для сборки под Windows — Visual Studio (C++) и Inno Setup 6, для Android — Android SDK с NDK 28.2 и `gomobile`, для Linux — WSL с Ubuntu 24.04.

Движок:

```
cd engine
go vet ./...
go test ./...
GOOS=linux go build ./... && GOOS=linux go vet ./...
GOOS=android GOARCH=arm64 go vet ./mobile
```

Интерфейс:

```
cd app
flutter analyze
flutter test
flutter run -d windows --dart-define=DEMO=true   # с демо-бэкендом, без службы
```

Код Dart форматируется `dart format --line-length 160`. Ядра (xray, sing-box, mihomo) в git не хранятся: сборка берёт их из `engine/testdata/bin`.

## Сборка и выпуск

Версия — файл `VERSION`, номер сборки — число коммитов (пользователь видит только версию).

```
powershell -ExecutionPolicy Bypass -File packaging\windows\build.ps1               # установщик Windows
powershell -ExecutionPolicy Bypass -File packaging\android\build.ps1               # APK для телефона (arm64)
powershell -ExecutionPolicy Bypass -File packaging\android\build.ps1 -Abi x86_64   # APK для эмулятора
powershell -ExecutionPolicy Bypass -File packaging\linux\build-wsl.ps1 -Ref main   # .deb, .rpm, Arch, .tar.gz (в WSL)
```

Выпуск целиком: `packaging\release.ps1 -Version X` собирает все системы и подписывает манифесты, `packaging\publish.ps1 -Version X` выкладывает релиз в [NezZeen/CoreShift-Release](https://github.com/NezZeen/CoreShift-Release). Подробности — в [packaging/README.md](packaging/README.md).
