# Версии и сборки CoreShift

## Как устроена версия

- **Номер версии** лежит в файле `VERSION` в корне, например `0.2.0`.
- **Номер сборки** — число коммитов в git. С каждым коммитом он растёт.
- **Коммит** — короткий хеш. Если собирали с незакоммиченными изменениями, к нему добавляется `-dirty`.

Все три зашиваются при сборке:

- **Установщик.** Файл называется `dist\coreshift-setup-0.2.0-b14.exe`, так что старые установщики не затираются. На последнем шаге установщик пишет «сейчас 0.2.0 (сборка 14) → будет 0.2.1 (сборка 20)». Перед установкой более ранней версии он переспрашивает, настройки и подписки при этом сохраняются.
- **Приложение.** Номер виден в боковой панели и в «Настройки → О программе». После обновления или отката приложение один раз пишет «CoreShift обновлён: …» или «Установлена более ранняя версия: …».
- **Служба.** Номер показывает команда `coreshiftd version`. Если версии приложения и службы разные, в настройках появится предупреждение.

## Ветки

- `main` — текущая разработка.
- `release/0.2.0`, `release/0.3.0`, … — код каждой выпущенной версии. Там же стоит тег `v0.2.0`.

## Команды

Собрать текущий код:

```
powershell -ExecutionPolicy Bypass -File packaging\windows\build.ps1
```

Выпустить версию: закоммитить всё, затем выполнить команду. Она запишет `VERSION`, сделает коммит, тег `v0.3.0` и ветку `release/0.3.0`, а потом соберёт установщик.

```
powershell -ExecutionPolicy Bypass -File packaging\release.ps1 -Version 0.3.0
```

Собрать любую прошлую версию, чтобы сравнить. Код берётся во временную копию, рабочая папка не меняется:

```
powershell -ExecutionPolicy Bypass -File packaging\build-version.ps1 -Ref v0.2.0
```

Посмотреть, какие версии есть:

```
git tag
git branch --list release/*
```

Ядра (xray, sing-box, mihomo) в git не хранятся, их около 200 МБ. Сборка берёт их из `engine\testdata\bin`.
